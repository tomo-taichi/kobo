# ADR-0009: 量産管理システム(Production Management System)

- Status: Draft(要レビュー)
- 関連: ADR-0008(Customer Portal ユーザーロール & アイソレーション)

## 1. 背景・目的

パリでの受注会終了後、受注を締め切ってから量産プロセスが始動する。量産プロセスは以下の大まかな流れで進む。

```
素材発注 → パターン印刷 → 裁断 → 縫製 → 仕上げ → 請求・支払い確認 → 発送
```

- 素材の発注とパターン印刷は太一が担当。
- 裁断・縫製・仕上げは商品モデルごとに担当者(社内従業員 or 外部委託会社)を割り当て、進捗を報告してもらう。
- この進捗はCustomer Portalでクライアントがリアルタイムに確認できる(ADR-0008の「Product progress」機能と連動)。

本ADRは、この量産プロセス全体を管理するBrand側の内部ページ群の仕様を定義する。

## 2. 用語・エンティティ定義(提案)

| エンティティ | 説明 |
|---|---|
| `Season` | 受注シーズン(既存) |
| `Order` / `OrderLine` | 受注(既存)。各OrderLineがどのProductionBatchに属するかを紐付ける必要あり |
| `Product`(Model) | 商品モデル(既存)。裁断コスト・縫製コストを「金額」→「時間」入力に変更 |
| `Material` | 生地・素材のマスタ。**色ごとに別レコード**として管理(同じ生地でも色違いは別計算) |
| `Supplier` | 素材の発注先。Materialに紐付く |
| `MaterialOrder` / `MaterialOrderLine` | シーズンごとの素材発注。必要数・在庫数・差分・最終発注数を保持 |
| `ProductionBatch` | **Model × Main Material × Color**の単位。量産の実行単位(例: Mountain Parka / Cotton Paper / Black × 10着) |
| `ProductionAssignment` | ProductionBatchごとの裁断者・縫製者の割り当て |
| `FinishingTask` | ProductionBatchに紐づく仕上げ6工程(テープ/ボタン/ボタンホール/手縫い/洗い/タグ)の完了フラグ |
| `Invoice` / `Shipment` | 顧客ごとの請求・発送。1顧客の注文が複数Batchに分かれて部分的に完成するケースに対応する必要あり |

**重要な設計方針:** パターン・裁断・縫製・仕上げは「ProductionBatch(Model×素材×色)」単位で進捗管理する。一方、請求・支払い・発送は「Customer(顧客)」単位で管理し、かつBatch分割(部分納品・部分請求)に対応する。この2つの管理単位の違いをデータモデルで明確に分離すること。

## 3. 機能仕様

### 3.1 素材発注ページ

- シーズンごとの受注商品から、必要な素材の合計数量を自動算出する。
  - 色違いの生地は別々に計算する(Material×Colorが計算単位)。
- 各Materialについて、現在の在庫(用尺・個数)を**手入力**し、「必要数 − 在庫数」の差分を自動計算する。
- 差分を確認した上で、最終発注数は**手入力**する(自動計算値をそのまま使わない前提)。
- 発注が確定したら、Supplierごとに素材をまとめて発注書(PO)を自動生成し、メールテンプレートも自動生成する。
- 一覧はSupplierごとにソート可能にする。

### 3.2 Production Master List

- 全商品をモデル別にソートした、印刷用の一覧ページ。量産チームが紙で確認するための一覧。

### 3.3 量産進捗管理ページ(Top / Kanban)

- 各ProductionBatchが現在どのStageにいるか一目でわかる画面(Kanban的な表示)。
- Stageを更新すると、該当Batchが自動的に次のStageに移動する。
  - 例: Mountain Parka(Black)の裁断が完了 → 自動的に縫製Stageへ移動。
- 裁断者・縫製者の割り当てもここで行う(通常は発注した生地の入荷タイミングまでに決定)。

### 3.4 Stage別ページ

Stage: **パターン / 裁断 / 縫製 / 仕上げ / 請求・支払い / 発送**

- パターン・裁断・縫製・仕上げ: **ProductionBatch(Model×Main Material×Color)単位**で更新。
  - 例: Model=Mountain Parka, Main Material=Cotton Paper, Color=Black, 発注合計10着 → 10着を1つの単位として同時に進める。
  - 色が変わる=生地が変わる=別Batchとして裁断も別々に行う。
- 請求・支払い・発送: **Customer(顧客)単位**で更新。
  - Batch分割に対応: 例えば顧客が20着注文していて10着分のBatchが先に完成した場合、その10着分だけ先に請求・支払い確認・発送できるようにする。

#### Priority(優先順位)と工数ベースのコスト計算

- パターン・裁断・縫製・仕上げの各Stageで、どのBatchを優先して進めるかのPriority(順序)を設定できるようにする。
- 商品ごとの完成までの**TOTAL作業時間**を、裁断コスト・縫製コストから算出する。
  - **変更点:** 商品設定において、現在「金額」で入力しているコスト項目を「時間」で入力する方式に変更する。
  - 金額 = 時間 × ¥2,000/時間 として自動算出する。
  - (既存商品データは金額→時間への手動での再入力が必要になる想定。自動変換はできない)

#### ステータス・フラグ一覧

| 項目 | 値・状態 |
|---|---|
| 生地入荷フラグ | 入荷待ち / 入荷済み |
| パターン状態 | 新規作成が必要 / 印刷が必要(データはあるが未印刷) / 完成済み |
| 裁断Status | Ready / Started / Finished |
| 縫製Status | Ready / Started / Finished |
| 仕上げStatus | Ready / Started / Finished |
| 仕上げ6工程 | テープ / ボタン / ボタンホール / 手縫い / 洗い / タグ(各々完了フラグをON/OFF。完了したものから消していく形のUI) |

- 仕上げの6工程は、商品によっては不要な工程もあるが、**現時点では全商品に対して6工程すべてを管理する**(不要な工程はチェックしないだけで運用する)。

#### 仕上げページ固有機能

- タグ発行(印刷用)機能: タグにはコンセプト名と混率(素材の配合比率)を併記して印刷できるようにする。
- クライアント(顧客)別にソートできるようにする。

## 4. Customer Portalとの連動(ADR-0008との関係)

ADR-0008で定義した「Product progress — 8 steps: PATTERN→CUT→SEW→FIN→READY→Invoiced→Paid→Shipped」は、本ADRで定義したProductionBatch単位の進捗管理と整合させる必要がある。具体的には、Customer Portal側の進捗表示は、顧客の注文内の各商品が属するProductionBatchの現在Stageを参照して表示する形に精緻化する。

**要確認:** ADR-0008時点の「8 steps」の粒度と、本ADRのStage(パターン/裁断/縫製/仕上げ/請求・支払い/発送)+仕上げ6工程の粒度は一致していない。Customer Portalでどこまで細かく見せるか(Stage単位のみか、仕上げの6工程まで見せるか)を決める必要がある。

## 5. 前提・要確認事項(要レビュー)

- パターンの状態値「すでに完成済みか」の表記を仕様上「診察済み」と記載していたが、誤字と判断し「完成済み」として整理した。相違ないか確認をお願いしたい。
- 工数×¥2,000/時間のレートは、裁断・縫製で共通と仮定した。工程ごとに異なるレートが必要か確認したい。
- 既存商品データのコスト(金額)→時間への移行は、手動での一括再入力が必要になる想定。件数が多い場合は移行手順を別途検討する。
- 請求・発送のBatch分割ルール(顧客の注文のうち、完成した分だけ先出しする際の請求書の分割方法・在庫管理との整合)は、実装前にもう一段具体化が必要。
- 本機能はBrand内部専用ページであり、ADR-0008のRLS方針(is_brand())の対象に含める。Customer Portalに見せる進捗情報は、読み取り専用の限定ビューとして別途アクセス制御を設計する。

## 6. 実装フェーズ分割案(推奨)

小さく確実に進めるため、以下の順番を推奨する。各フェーズはテスト・確認・コミットを経てから次に進む。

1. **データ基盤:** Material / Supplier / ProductionBatch エンティティの追加、Product の コスト→時間フィールドの変更(マイグレーション)
2. **素材発注ページ:** シーズン別必要数の自動算出、在庫入力、差分計算、Supplier別発注書・メールテンプレート生成
3. **量産進捗管理(Top/Kanban)ページ + Production Master List:** Stage自動遷移、担当者割り当て
4. **Stage別ページ(パターン/裁断/縫製/仕上げ):** Priority設定、工数ベースのコスト表示、各Statusフラグ
5. **仕上げの詳細管理:** 6工程チェックリスト、タグ発行(印刷・混率表記)、クライアント別ソート
6. **請求・支払い・発送(Batch分割対応):** 顧客単位管理、部分請求・部分発送
7. **Customer Portal連携:** 進捗表示の精緻化(ADR-0008の8 stepsとの整合)
